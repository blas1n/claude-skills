# 개발용 지표 개선이 고정된 대표 사례를 팔아넘길 수 있다

## Problem (2026-10-21, hots-replay-analysis PR #24)

운영 판단 탐지기 v4 튜닝 중 "15초 안에 클릭했던 곳으로 돌아가면 새 판단이 아니라 지속" 규칙을 넣었다.
개발용: continuation 오탐 7→5, 존재 정밀도 0.816→0.848. 채택 직전, 실제 리플레이 회귀 테스트가 실패했다:
대표 경기의 objective-1 진입(검토자 '높음', v3 TP)이 보류됐다. 플레이어가 173초에 지점 근처에 있다가
라인으로 갔다가 187.9초에 **재합류**한 것 — 규칙은 이를 "원래 목적지 복귀"로 읽었다. 반경을 20→10으로
줄여도 같은 결과(실제 원인은 반경이 아니라 "사이에 다른 목적지가 있었는가"를 보지 않는 것).
두 경우를 가르는 기준이 데이터로 안 보여 규칙을 버렸다.

## Rules

1. **대표 회귀 사례를 정확한 값으로 고정한 테스트**를 두고, 개발용 지표가 오른 변경도 그 테스트를 통과해야 채택한다. 집계 지표는 "FP 2 감소 > TP 1 손실"로 계산하지만, 사례의 가치(검토자 높음, 사용자에게 보여 준 보고서의 판단)는 집계에 없다.
2. 억제 규칙(지속·중복·무빙 간주)은 **"무엇과 무엇을 같게 보는가"를 사례로 반례 검사**하라: 떠났다 돌아온 것(재합류)과 잠깐 흔들린 것(복귀)은 좌표상 같다. 사이 구간의 행동을 보지 않으면 구분 못 한다.
3. 실패한 시도는 개발용 수치와 함께 문서에 남긴다("버림" 표). 다음 사람이 같은 규칙을 다시 시도하지 않게.
4. **기준선 재채점의 매핑 편향:** 옛 이름(`play_elsewhere`)을 새 종류 집합(`{lane, rotation}`)으로 매핑하면 기준선은 어느 쪽이든 정답이 된다. 실제로 검토자 B 기준 종류 정확도 결론(v3 0.76 > v4 0.65)이 이 관대함에서 나왔다. 보고서에 "기준선에 유리한 매핑"임을 명시하고, 결론을 쓰기 전 혼동 행렬로 오류가 어디서 오는지 확인하라.
5. **수치는 손으로 옮기지 말고 결과 파일에서 다시 출력해 대조**하라. 이번에 README 에 기억으로 쓴 두 수치(라벨 종류 분포, 억제 단계 합계 33→실제 28)가 틀렸다.
