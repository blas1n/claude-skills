# 격자 샘플 트랙은 앵커 옆에 구멍이 있다

## Problem

- 증상: 시간 슬라이더를 움직이면 관측과 관측 사이(1–2초 간격)나 창 끝 근처에서 개체가 잠깐 "미확인"이 된다. 응답은 60초 창인데 60 KB를 넘는다.
- 근본 원인
  1. 추정점 = 격자 시각 ∩ (a.t+tol, b.t−tol). 첫 격자점 p 가 a.t+1 보다 뒤면 [a.t+tol, p−step/2] 가 어느 쪽에도 안 덮인다. 간격이 step+2·tol 보다 짧으면 점이 0개.
  2. 창 끝: 다음 관측 b 가 창 밖이면 클라이언트가 마지막 격자점 이후를 이을 앵커가 없다.
  3. 객체 행(`{"id":…, "grade":"observed", …}`)은 키 이름·상수 등급이 행마다 반복돼 크기의 절반 이상이 된다.
- 흔한 오해: "격자가 1초면 촘촘하다", "관측 우선 규칙은 안전하다". 두 규칙이 맞물려 구멍을 만든다.

## Solution

1. 서버: 구간에 유효한 격자점이 없으면 **중점 하나**를 넣는다(중점은 양쪽 관측에서 tol 이상 떨어짐이 보장될 때만).
2. 서버: 창 안 관측 + 개체별 **창 앞 마지막·창 뒤 첫 관측**을 `in_window: false` 앵커로 포함한다. 뒤쪽은 미래 정보라고 명시. 테스트: 추정/공백이 참조하는 모든 관측 id 가 응답에 있다.
3. 클라이언트: 같은 추정 행 안에서는 [from_obs, …points, to_obs] 를 선형으로 이어 **표시만** 한다(상태는 계속 estimated, 새 추정 아님).
4. 대량 배열은 열 형식 블록 `{grade, hindsight, columns, rows}` 로. 행 단위 신뢰 등급은 블록 수준에 한 번. 그래도 크면 조용히 자르지 말고 (점 간격 넓힘 → 창 단축) 순서로 `reductions` + `paging.next_start_s` 기록.
5. 모델 테스트: 모든 추정 구간 [from.t, to.t] 를 0.25초로 훑어 `unknown` 이 하나도 없어야 한다.

## Key Insights

- 구멍 재현 테스트는 **격자를 관측 시각에 정렬**해야 빨개진다. 창 시작 29·step 2 는 우연히 31 이 유효해 결함 전에도 초록이었다(→ [[a-check-that-cannot-flip-is-not-measuring-anything]]). 창 시작을 관측 시각(30)으로 옮기자 RED.
- 창 경계 결함은 합성 데이터보다 **실제 표본 전체 스윕**(모든 창 × 모든 구간)에서만 나왔다.
- 크기는 먼저 필드별 바이트를 분해해 본다(`{k: size(v)}`). 이번엔 추정 메타데이터가 1위였다.

## Case: "no line across a gap" checked at the gap's middle cannot fail (2026-10-26, PR #38 follow-up)

최근 경로(trail)가 30초 공백·불연속 이동을 가로지르지 않는지 공백 **중간** 시각에서 검사했더니, 경로를 구간과 무관하게 한 줄로 잇도록 망가뜨려도 초록이었다. 중간 시각에는 공백 **뒤** 점이 아직 "과거"가 아니라 경로에 들어올 수 없기 때문이다. 잘못된 연결은 공백 **직후**(끝+2초)에만 보인다 → 두 시각을 모두 검사하자 망가뜨린 버전에서 RED. 또 실제 데이터의 불연속 공백은 전부 1초 미만(돌진)이라 "공백 중 마커 0개"는 틀린 단언이었다: ±tol 안의 양쪽 실제 관측은 정당하다. 단언은 "마커가 있다면 그 공백 양끝 관측 id 중 하나, 추정은 없음"으로.
