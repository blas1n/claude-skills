# 빠진 종료 이벤트는 타임스탬프가 아니라 구간이다

## Problem

2026-10-23, HotS 리플레이 매크로 분석(PR #29). 레오릭은 죽어도 영웅 유닛이 죽지 않고(망령) `SUnitRevivedEvent`도 남기지 않아, 사실 계층이 다음 사망까지 "사망"으로 읽었다.

- 첫 계획: 일반 영웅 8,000여 건에서 잰 레벨별 부활 시간(최빈값 93~98% 일치, 4개 빌드 동일)을 더해 **레오릭 부활 시각을 derived 이벤트로 만든다.**
- 실제: 상태 배타적 증거로 인스턴스별로 재 보니
  - 타이머 이후 망령 전용 입력: 0/128 → 타이머는 **상한**으로는 옳다
  - 타이머 이전 일반 능력 입력: 82/163, 최대 25.7초 일찍; 살아 있는 영웅만 만드는 유닛 생성도 38건이 타이머 전
  - → 부활 시점이 **흩어져 있다.** 표준값을 꽂았으면 절반의 사망에서 "실제보다 늦은 부활"을, 원인 미상인 채로 확신했을 것이다.
- 흔한 오해: "다른 엔티티에서 그렇게 일관된 값이면 이것도 같겠지". 종료 이벤트가 없는 이유(특수 메커니즘)가 지속시간도 바꾸는 경우가 많다.

## Solution

1. **상태 배타적 증거를 찾고, 배타성부터 검증한다.**
   - A 상태에서만 가능한 입력(망령 전용 능력 ID), B 상태에서만 생기는 효과(살아 있는 영웅만 소환하는 유닛).
   - 배타성 검사: "B 효과가 마지막 A 입력보다 먼저 나온 경우 = 0", "A 입력이 B 입력 뒤에 나온 경우 = 0", "사망 직후 2초 안 B 효과 = 0"(사망 직전 시전이 늦게 생성되는 경우 배제).
2. **인스턴스별 분포를 잰다.** 첫 B 증거 − 표준값, 마지막 A 증거 − 표준값. 0에 몰려 있으면 표준값을 써도 되고, 흩어져 있으면 아래로.
3. **3값 상태로 모델링한다.** dead / uncertain / alive. 시작 이벤트부터 uncertain, 확정은 (a) 관측된 B 효과(observed) 또는 (b) 검증된 상한 만료(derived)로만. 활동 존재(명령)는 어느 쪽 근거도 아니다.
4. **하류 소비자가 uncertain 을 숫자로 뭉개지 않게 한다.** 집계(생존 수)는 불확실 묶음을 따로 두고, 불확실이 없으면 출력 모양을 이전과 같게(다른 엔티티 산출물 바이트 동일 확인). 불확실 대상의 파생 판단(대안 실행 가능성)은 unknown.
5. **같은 구조적 서명으로 전 엔티티를 훑는다.** "시작 이벤트 대비 네이티브 종료/짝 이벤트 비율"을 엔티티별로 세면 이상치가 바로 보인다. 이번엔 Lost Vikings(바이킹마다 PlayerDeath, 부활은 비주 유닛에만 기록 → 플레이어가 첫 사망부터 영구 사망)라는 **더 큰 버그**가 나왔다.

## Key Insights

- 일반 집단의 높은 일관성은 예외 엔티티에 대한 증거가 아니다. 예외가 예외인 이유를 먼저 의심하라.
- "활동이 있다 → 살아 있다"는 정상 엔티티에서 먼저 반증해 보라. 일반 영웅도 사망 중 입력(지연·소환수 조종)이 수천 건 있었다. 입력 존재가 아니라 **상태 배타적** 입력·효과만 근거가 된다.
- 상한(타이머)만 확실하면, 상한 확정은 "늦게 확정"하는 보수적 오류만 낸다 — 이른 확정(근거 없는 확신)은 원천 차단된다. 방향이 한쪽인 오류를 고르는 설계.
- 집계 점수(TimeSpentDead)로 교차검증하기 전에 정상 엔티티에서 그 점수가 측정값과 맞는지 먼저 보라. 일반 영웅에서도 ±수십 초 어긋나 쓸모가 없었다.
- 배타적 증거 중 빌드·버전마다 바뀌는 식별자(능력 ID)는 감사 근거로만 쓰고 운영 규칙에는 넣지 않는다.

## Red Flags

- "다른 것들은 다 N초니까 이것도 N초를 더하자"
- 종료 이벤트 대신 "다음 활동이 보이면 복귀"로 판정하려 할 때
- 상태 복원 코드가 시작 이벤트는 엔티티 단위, 종료 이벤트는 하위 유닛 단위로 기록되는 엔티티(다중 유닛)를 만날 때
- 파서에 "hero-specific mechanics possible" 같은 교차검사 경고가 이미 찍혀 있는데 하류가 무시하고 있을 때

## Follow-up case: 상태를 관측 사실에 붙일 때 (같은 PR 보완)

생존 3값 상태를 위치 관측에도 붙이자(사망 후에도 유닛이 남는 영웅의 위치를 "살아 있는 영웅 위치"로 쓰지 않으려고), 1차 스윕에서 **판단 1,741건 중 수백 건의 패킷이 바뀌었다** — 특수 영웅이 없는 경기까지. 원인은 로직이 아니라 **설명문(note) 두 줄을 무조건 바꾼 것**이었다. 직렬화되는 산출물에서 설명문은 데이터다.

- 새 상태는 **기본값이 아닐 때만** 필드로 붙인다(alive = 필드 없음). 그래야 일반 엔티티 사실이 바이트 단위로 그대로다.
- 설명문 보강도 **그 상태가 실제로 등장할 때만** 덧붙인다.
- 영향 스윕은 "바뀐 경기에 특수 엔티티가 있는가"로 분류해 보라. 없는 경기가 하나라도 바뀌었으면 의도치 않은 전역 변경이다.
- 경계 사례: 일반 엔티티의 "쓰러진 지점" 관측이 사망 이벤트와 **같은 루프**에 찍히면 새 규칙이 그것을 dead로 바꿔 버린다(15점). 경계 루프 ±N 은 기존 의미를 유지하는 예외로 둔다.
