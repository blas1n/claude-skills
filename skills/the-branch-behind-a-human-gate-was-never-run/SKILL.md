# 사람 뒤의 분기는 아직 한 번도 안 돌았다

## Problem

BSVibe 2026-09-02, 앞 세션이 야간 러너를 만들었다. 설계는 훌륭했다 — 비밀은
Keychain 에서만 읽고, `trap` 으로 teardown 하고, **자격증명이 없으면 알람 없이
크게 로그만 남기고 SKIP** 한다(사람을 기다리는 것은 장애가 아니므로).

```bash
password=$(security find-generic-password -s "$SERVICE" -a "$EMAIL" -w 2>/dev/null)
if [ -z "$password" ]; then
  echo "SKIP: 라이브 E2E — Keychain 에 자격증명이 없다."
else
  ...
  cd "$PWA" && pnpm test:e2e:live     # ← 여기가 한 번도 안 돌았다
fi
```

그 세션의 실증 기록:

> *"실증: 기대 포트를 틀리게 바꾸면 exit 1 + FAIL 로그 · **자격증명 없이 돌리면
> 렌더링 둘 다 통과 + exit 0 + SKIP 안내**"*
> *"⭐ launchd 와 동일한 환경으로 돌려 확인했다 — `env -i HOME=… PATH=<plist PATH>` 로"*

PATH 까지 실제 데몬 환경으로 검증한 **꼼꼼한** 세션이다. 그런데 검증은 전부
**`else` 바깥**에서 이뤄졌다.

## 실측 (2026-09-03)

자격증명을 넣고 돌리자 즉시:

```
sh: playwright: command not found
```

`@playwright/test` 가 `package.json` 에 **선언만** 돼 있고 이 머신엔 설치돼
있지 않았다. `node_modules` 는 **7월 7일자**, 그 패키지는 **9월에 추가**됐다 —
빠진 devDep 이 13개 중 **정확히 이것 하나**.

CI 는 매번 fresh install 하므로 초록이었다. 로컬 소비자는 그 야간 러너 하나뿐이고,
그 러너는 **그 줄에 도달한 적이 없었다.**

⇒ 형님이 Keychain 에 비밀번호를 넣는 **바로 그 순간**, 러너는
`command not found` 로 죽었을 것이다. 그리고 그건 형님이 방금 한 행동 탓으로
보였을 것이다.

## 왜 놓치는가

게이트가 있는 코드는 **두 개의 프로그램**이다:

| | 실행 횟수 | 검증 난이도 |
|---|---|---|
| 값이 없는 경로 | 매번 | 쉽다 — 그냥 돌리면 된다 |
| 값이 있는 경로 | **0회** | 값이 필요하다 |

그런데 **초록은 한 덩어리로 보인다.** `exit 0` 과 "SKIP 안내가 잘 나온다"는
전체가 건강하다는 인상을 주고, 실제로는 **한 번도 안 밟은 절반**을 가린다.
게이트가 정중할수록(알람 안 울림, 로그 예쁨) 더 그렇다.

이건 `local-green-is-not-evidence-when-the-backend-is-gated` 의 자매 결함이고,
`capability-guard-must-assert-presence`(가드가 "없음"만 검사하면 정작 능력 0개를
못 잡는다)와 같은 모양이다. 다만 여기서 게이트를 여는 건 **사람**이라, 결함이
발화하는 시점이 **가장 나쁜 때**로 예약된다 — 사람이 막 수고를 들인 직후.

## 규칙

**게이트 뒤의 분기를 한 번은 강제로 열어라.** 진짜 비밀이 없어도 된다:

1. **대역 값으로 분기 안까지 들어가라.** 인증이 401 로 실패해도 좋다 — 목적은
   *인증 성공*이 아니라 **그 줄들이 존재하고 실행 가능한지**다.
   `BSVIBE_E2E_PASSWORD=dummy` 로 돌리면 `command not found` 는 즉시 잡힌다.
2. **못 넣으면 도구 존재만이라도 게이트 앞에서 단언하라.**
   ```bash
   command -v playwright >/dev/null || fail "playwright 없음 — 자격증명이 들어와도 못 돈다"
   ```
   게이트 **앞**이 핵심이다. 뒤에 두면 같은 함정에 다시 걸린다.
3. **"SKIP 을 실증했다"를 실증 목록에 그대로 쓰지 마라.** 체크리스트에
   *"자격증명 없이 돌리면 SKIP + exit 0"* 만 적혀 있으면, 그 문장은 **뒤 절반이
   미검증이라는 사실을 숨긴다.** 두 줄로 나눠 적어라:
   - [x] 값 없음 → SKIP, 알람 없음
   - [ ] **값 있음 → 실제로 끝까지 돈다** ← 이게 남아 있음을 보이게

## 세는 법

사람 손이 필요한 기능을 만들 때 물어라:

* 이 값이 들어오면 **처음으로 실행되는 줄**이 몇 줄인가?
* 그 줄들은 **어떤 환경**을 가정하는가(도구·PATH·네트워크·권한)?
* 그 가정 중 **CI 에서만 참인 것**이 있는가? (fresh install 이 대표적)
* 값이 없어도 그 가정을 **지금 확인**할 수 있는가?

마지막 질문의 답은 거의 항상 "그렇다"이다.
