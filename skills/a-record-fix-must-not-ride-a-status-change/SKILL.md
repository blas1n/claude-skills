# A record fix must not ride a status change

## Problem

- 증상: 개발 사례(s08: 치유사의 아군 대상 명령이 무시돼 "교전 100%"로 기록)를 고치려고 `ally_support`를 활동 상세로 넣고 교전과 "호환"으로 묶었다. 유닛 테스트·실사례 회귀 모두 초록, 논리도 그럴듯("치유사에게 치유는 교전 참여"). 269경기 sweep 에서 검토 후보 240→262, 복구 28건 — 개선처럼 보였다.
- 경기 단위 holdout(블라인드 AI 2명): 새 오탐 4건(p25·p36·p53·p67)이 전부 이 규칙, 복구는 1건(p38). 지원만 남은 얇은 묶음·후퇴하며 치유를 "교전 지속"으로 읽었다.
- 근본 원인: "기록을 정확히" 고치는 일과 "그 클래스가 판정(지속/근거 사슬/prior 존재)에 기여" 하는 일을 한 번에 했다. 후자는 새 규칙이고 따로 증명돼야 한다. sweep 의 변경 대부분(64/95)이 이 상태 효과였다.
- 흔한 오해: 오분류를 고치는 것은 순수한 정확성 개선이므로 결과도 좋아질 것이다.

## Solution

1. 오분류 수정은 먼저 **기록 전용 필드**로: `ally_support_commands: 5` 처럼 옆에 세고, 활동·상세·근거 사슬은 그대로 둔다.
2. 그 클래스를 판정에 넣는 것은 별도 규칙으로 등록하고, sweep 에서 상태가 바뀐 사례를 holdout 층(stratum)으로 뽑아 평가한다.
3. holdout 이 반증하면 사전 등록된 이전 동작으로 되돌린다(이전 동작은 같은 라벨로 이미 채점돼 있으므로 holdout 튜닝이 아님). 기록 필드는 남긴다.
4. before/after 층화 시 "changed" = **상태 클래스** 차이(`status.split(":")[0]`). 거부 사유 이름 변경(`no_distinct_alternative`→`trigger_unrelated`)을 변경으로 세면 변경 층이 11→66으로 부풀어 의미 없는 사례가 표본을 채운다.
5. 임계값 경계 사례(gt30: 거리 34, 기준 30)는 반대 방향 사례가 같은 거리에 있는지 먼저 찾는다(s31 오탐: 34.4). 있으면 임계값으로 못 고친다 — 다른 판단 시점 근거(처치 크레딧에 대상의 교전 상대가 있는가)가 둘을 가르는지 본다.

## Key Insights

- "원칙적으로 맞는" 확장도 판정 경로에 들어가면 새 규칙이다. 유닛 테스트는 의도한 모양만 증명한다 — 얇은 묶음·후퇴 같은 실제 분포는 holdout 만 본다.
- sweep 변경의 대부분이 한 규칙에서 나오면, 그 규칙이 holdout 결과를 지배한다. 규칙별로 holdout 에서 작동한 사례 수를 세라 — 0 이면 "평가되지 않음"으로 보고해야 한다(이번 처치 크레딧 규칙).
