# 공개 레포의 보안 수정은 배포 전에 공개된다

## Problem

BSVibe(2026-10-15): 모델 계정 SSRF 를 고치고 커밋 메시지에 이렇게 적었다 —
*"테넌트가 postgres · 169.254.169.254 · 호스트 Ollama 로 백엔드 요청을 보낼 수 있었다"*.
PR 을 열기 직전에 레포가 **PUBLIC** 임을 확인했다. 머지까지 CI ~25분 + 자동 배포 2분 동안,
prod 는 아직 취약하고 공격 방법은 공개 PR 에 적혀 있게 된다.

내부 레포에서 굳은 습관(커밋에 사고 경위·재현을 자세히)이 공개 레포에서는 그대로 공시가 된다.

## Solution

1. 보안 수정을 커밋/푸시하기 **전에**: `gh repo view <owner>/<repo> --json visibility -q .visibility`
2. PUBLIC 이면:
   - 제목·본문을 **동작 기술**로: "모델 계정 엔드포인트는 공개 주소만 받는다" (O) / "SSRF 로 내부망 접근 가능" (X)
   - 커밋은 `--amend` 로 다시 쓴 뒤 푸시(푸시 전이면 흔적 없음)
   - 재현 단계 · 내부 호스트명 · 우회 방법은 비공개 채널(인수인계 · 사적 메모)로
   - 머지까지의 창을 짧게 — CI 가 초록이면 바로 머지
3. 코드 자체(테스트 이름 · 독스트링)도 무엇을 막는지 드러낸다. 완전히 숨길 수는 없으니
   **설명의 상세도와 노출 시간**을 줄이는 것이 목표다.
4. 이미 공개된 뒤라면: 숨기려 하지 말고 배포를 앞당긴다(force-push 는 PR ref 에 남는다 —
   `force-push-does-not-erase-what-pull-refs-hold`).
