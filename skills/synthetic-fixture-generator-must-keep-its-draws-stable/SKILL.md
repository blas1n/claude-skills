# 합성 픽스처 생성기는 뽑는 순서를 안정적으로 유지해야 한다

## Problem

실데이터(외부 API 응답, 실제 플레이어) 픽스처를 공개 저장소에 남길 수 없어 생성기로 숫자를 다시 뽑고 신원을
가짜로 바꿨다. 그 다음 테스트 기대값 수백 개를 새 데이터에 맞췄다. 그런데 생성기에서 깨진 불변식(바꾸면 안 되는
키, 합계 관계)이 하나씩 드러날 때마다 고쳐서 다시 생성하면, **고친 곳과 무관한 값까지 전부 바뀌어** 맞춰 둔
기대값이 다시 무효가 됐다.

- 증상: 키 하나를 "보존"으로 바꿨을 뿐인데 다른 파일의 숫자가 다 달라짐. 가짜 ID 대응표도 바뀌어 테스트 코드에
  치환해 둔 ID가 어긋남.
- 근본 원인: 파일마다 `random.Random(seed)` 하나로 순회하며 뽑는다. 보존 키가 늘면 그 키에서 뽑던 한 번이
  사라지고, 그 뒤 모든 값이 한 칸씩 밀린다. 가짜 ID도 같은 흐름에서 뽑았으면 함께 밀린다.
- 흔한 오해: "결정적(seed 고정)이니 재생성해도 같다." 같은 건 코드가 그대로일 때뿐이다.

## Solution

1. **보존 키를 나중에 추가할 땐 뽑고 버린다**: `v = redraw(o, rng); return o if key in KEEP_DRAWN else v` —
   주석으로 이유를 남긴다(이후 값이 안 밀리게).
2. **관계 수정은 후처리 + 별도 시드**: 상성 쌍 합계, 처치=킬+어시, 패배율 의미, 팀 레벨 단조 증가, 역할별 승률 →
   전체를 다 뽑은 뒤 `Random(sha(seed + ":post"))`로 고친다. 후처리를 늘려도 본 흐름은 안 움직인다.
3. **가짜 ID는 원래 값의 해시로**: `lo + sha(f"id:{real}") % span` — 실행 순서와 무관하게 안정적이고 파일 간 일관.
4. **재생성은 항상 원본(머지 전 `origin/main`)에서**: 이미 합성된 파일을 다시 합성하지 말고, HEAD가 바뀐 뒤엔
   `git show HEAD:`가 원본이 아님을 기억한다. 이름을 바꾼 파일은 원본 경로 → 새 경로 매핑으로.
5. **테스트가 필요로 하는 상황은 시나리오로 명시**: 원래 픽스처에 손으로 넣어 둔 상황(보정된 영웅, 얇은 구간,
   불이익 조합, 얇은 지역)은 무작위로는 안 나온다. 경로별 함수로 명시하고, 파생 집계(meta 카운트)는 원래
   수집기 규칙으로 다시 센다.
6. 기대값 수정은 영역별(pytest / vitest / e2e)로 병렬 에이전트에 맡기되, "값 고정이 아니라 생성기가 불변식을
   깬 경우는 고치지 말고 보고"라고 명시 → 보고를 모아 생성기를 한 번에 고친다.

## Key Insights

- 숫자만 바꿔서는 안 끝난다. 실데이터는 이런 데로도 샌다:
  - **순서**: 값 순으로 정렬된 dict(영웅→피해량)의 키 순서 = 실제 순위. 새 값으로 다시 정렬한다.
  - **문장**: hovertext·리포트 본문·"88 days, 9 hours" 같은 문자열 속 숫자.
  - **이름**: 파일명(`api_player_<실명>.json`), 테스트 코드 리터럴, 대소문자·`%23`·전각 `＃` 변형, `#` 없는 단독 이름.
  - **주변 문서**: 체크리스트에 남은 비공개 전환 플레이어의 태그, 남의 사이트 캡처 PNG.
- 이력 정리 목록(실제 배틀태그 치환 규칙)은 그 자체가 개인정보다 — 저장소에 커밋하지 말고 비공개 채널(예약
  작업 프롬프트)에 둔다.
- `data/` 같은 데이터 디렉터리를 통째로 지우기 전에, 테스트가 그 안의 **비민감 파일**(게임 이름표 등)을 읽는지
  확인한다. 지울 하위 경로만 목록으로 만들고, 테스트·서버 설정은 합성 데이터 경로를 보게 바꾼다.
- `git filter-repo --strip-blobs-with-ids`로 "경로는 남기고 옛 내용만" 지울 때, 보존 목록은 HEAD **트리 전체**
  blob으로 잡는다 — 같은 내용이 다른 경로에 살아 있으면 그것까지 지워진다.
- 사본 mirror에서 절차 전체를 미리 돌리고, 정리된 클론에서 테스트를 돌려야 절차가 맞는지 안다.
  강제 푸시만으로는 GitHub `refs/pull/*`가 옛 커밋을 계속 잡는다 → Support 요청 필요.

## Red Flags

- "생성기 버그 하나 고치고 재생성" 뒤 무관한 테스트가 대량으로 다시 깨짐
- 가짜 ID 대응표가 실행마다 달라짐
- 생성기가 HTTP status, pick 순서, map id, 페이지 정보 같은 열거값을 바꿈
- 합성 후에도 리스트/dict 순서, 문자열 속 숫자, 파일명에 원본이 비침
- 데이터 디렉터리 삭제를 계획하면서 그 디렉터리를 읽는 테스트를 세어 보지 않음
