# 지적은 재현될 때만 센다

## Problem

BSVibe 운영(2026-11)에서 실측한 두 가지:

* **에이전트의 테스트는 에이전트의 사각지대를 공유한다.** 한 주 동안 리뷰가 찾은 진짜 high 4건이
  전부 초록 테스트와 통과한 요구사항 판정을 거쳐 나왔다 — 운영에서 한 번도 호출되지 않는 함수
  (테스트가 직접 불렀다), 소유하지 않은 트랜잭션 커밋(테스트는 경합만 봤다), 동시 항목의 빈 목록
  (테스트는 한 번에 하나씩 판정했다), 독스트링 속 이름을 호출로 센 것(그런 입력이 테스트에 없었다).
* **도구 없이 diff 만 읽는 리뷰어는 추측한다.** 같은 거짓 high 가 한 PR 에서 세 번 나왔다 —
  diff 밖의 `_hits` 가 이미 하던 일을 "없다"고 했다.

## Solution

변경을 **깨 보려는** 별도 검증자를 두고, 모든 지적에 실행 가능한 재현을 붙이게 한다. 판정은
모델이 아니라 하네스가 한다. 아래 규칙은 하나하나가 실제 거짓 확인을 막으려고 생겼다:

1. **재현 없으면 지적 없음.** 테스트 파일 또는 명령 + 결함을 증명하는 출력(`exit_code`,
   `contains`, `not_contains`).
2. **변경 전 대조.** 같은 재현을 변경 *전* 트리 사본에서 다시 돌린다. 변경 전에도 같은 결과면
   변경과 무관하다 — "텍스트를 찾는 grep" 이 대표적. 변경 전에 수집조차 안 되는 테스트(변경이
   추가한 것을 import)는 그 사실을 적고 인정할 수 있다. **명령형 재현이 변경 전에 실행 불가면
   절대 인정하지 않는다.**
3. **기대 근거.** "변경 후에만 성립" 은 변경이 동작을 *바꿨다* 는 증거일 뿐 *틀렸다* 는 증거가
   아니다. 지적마다 기대 동작의 출처를 적게 한다: 요청 원문 인용(공백 정규화 후 20자·3단어 이상 —
   짧은 인용은 아무 데서나 찾아진다), 변경 전 통과하고 변경 후 실패하는 기존 테스트, 또는 요청이
   건드리지 않은 코드의 `file:line`. 기계적으로 확인한다.
4. **의도 충돌 판정.** 별도 판정자에게 요청 *전체* 를 주고 묻는다: 재현이 기대하는 동작이 요청이
   바꾸라고 한 동작과 충돌하는가? 검증자가 인용한 항목이 아니라 **다른 요구사항** 이 새 동작을
   요구하는 경우를 놓치면, 요청된 변경이 "회귀" 로 확인된다(실측 2회 연속).
5. **검증자는 고칠 수 없다.** 임시 디렉터리에 테스트 파일만 쓴다. 트리 지문을 전후로 비교하고,
   재현은 항상 버리는 사본에서 돌린다. 상태를 바꾸는 git(`stash`, `checkout`, `reset`)도 금지 —
   변경 전 트리는 하네스가 만든다.
6. **"실행 안 됨" 은 "틀림" 이 아니다.** import·수집 오류로 죽은 재현은 그 이유로 따로 적는다.
   단, 정상 종료(exit 0)한 명령을 출력 글자만 보고 "실행 안 됨" 으로 보면 안 된다.
7. 실행이 남기는 부산물(`__pycache__`, `.pytest_cache`)은 변조가 아니다 — 지문에서 뺀다.

### 도구

`blas1n/claude-plugins` 의 `repro-verify` 플러그인이 위 규칙을 구현한다:

```text
/plugin marketplace add blas1n/claude-plugins
/plugin install repro-verify@blas1n-plugins
/adversarial-verify [base] [이슈번호|요청파일]
/guard-check [base]        # 비테스트 변경을 되돌려도 새 테스트가 통과하는가
```

플러그인 없이 손으로 할 때도 순서는 같다: 재현 작성 → 변경 후 실행 → 기준 커밋 사본(`git worktree`
또는 `git archive`)에서 실행 → 근거 확인 → 의도 충돌 확인 → 그때서야 결함이라 부른다.

### 결과 읽기

* 확인된 지적은 테스트가 증명한 결함이다. 고치고, 재현은 회귀 테스트로 남긴다.
* 미확인 지적은 의심일 뿐이다. 이유부터 읽어라 — "변경 전에도 같은 결과", "요청된 변경과 충돌"
  은 대개 리뷰어가 틀렸다는 뜻이다.
* 빈 결과는 "재현 가능한 결함을 못 찾았다" 이지 "변경이 옳다" 가 아니다.
