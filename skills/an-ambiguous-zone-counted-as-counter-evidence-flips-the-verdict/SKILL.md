# 애매한 구역을 반대 근거로 세면 판정이 뒤집힌다

## Problem

hots P5-C(파멸의 탑 레오릭 사례)에서 "같은 시간대에 아군 4명이 바텀 중심으로 활동했다(H2)"를 판정했다.

- 지역은 기존 `lane_of`로 정했다. 가장 가까운 라인이 2위보다 뚜렷이 가깝지 않으면 `between_lanes`를 낸다.
- H1(이동) 규칙은 `between_lanes`를 "라인 아님"으로 건너뛰었다.
- H2 규칙은 "관측된 아군 중 바텀이 아닌 것이 하나라도 있으면 바텀 밖 배치"로 셌다 → **`conflicts_with_observation`**.
- 분해해 보니 바텀 밖 관측 70칸 중 **40칸이 `between_lanes`**였고, 대부분 바텀과 미드 사이 공성 캠프(y≈70) 근처였다. 진짜 다른 라인(미드) 관측은 28칸이었고, 경기 초반·750초 이후에 몰려 있었다.
- 같은 데이터, 같은 분류기인데 "애매함"을 어느 쪽에 넣느냐로 판정이 **충돌 ↔ 간접 지지**로 갈렸다.

## Solution

1. **판정이 예상과 다르면 반대 근거를 범주별로 분해한다.** "목표 밖"을 `다른 확정 범주`와 `애매/미분류`로 나눈 개수를 본다.
2. **규칙 사이의 정의를 맞춘다.** 한 분석 안에서 같은 분류기 출력(`between`)은 모든 판정에서 같은 뜻(미분류)이어야 한다. 반대 근거는 "다른 확정 범주"만 센다.
3. **원래 규칙을 지우지 말고 민감도로 남긴다.** 예: `H2`(주 규칙) + `H2_sensitivity_strict`(애매 구역을 반대 근거로 세는 규칙)을 둘 다 출력하고, 보고서에 둘 다 쓴다.
4. **사후 수정을 공개한다.** "첫 결과를 본 뒤 규칙을 바꿨다"는 사실, 이유(정의 불일치), 이전 결과를 보고서·한계 문서에 쓴다. 임계값도 그 사례를 보며 정했다면 다른 데이터에는 미리 고정해 적용해야 한다고 적는다.
5. **애매 구역을 목표 범주로 승격하지 않는다.** "캠프 근처니까 바텀 운영"처럼 도메인 지식으로 메우면 정석 하드코딩이 된다. 미분류로 두고, 세분화가 필요하면 원본 좌표(캠프 Init 위치 등)로 별도 표시만 한다.
6. 테스트로 고정: 애매 구역 하나만 있는 배치가 주 규칙에선 `partial_or_unclassified`, 엄격 규칙에선 `observed_outside_bottom`이 되는지 둘 다 단언한다.

## Key Insights

- 분류기의 "애매함" 출력은 중립이 아니다. 그것을 받는 **판정 규칙**이 어느 쪽 증거로 쓰는지가 결론을 정한다.
- "반대 증거 > 지지 증거"형 판정은 애매 구역이 넓을수록 반대 쪽으로 기운다(엄격 규칙의 비대칭).
- 결과를 보고 규칙을 고치는 것 자체보다, **고친 사실을 숨기는 것**이 문제다. 두 결과를 같이 내면 독자가 판단할 수 있다.

## Red Flags

- 판정 함수가 `status != target`을 곧바로 반대 근거로 세는 코드
- 같은 분류기 출력이 판정마다 다른 버킷에 들어갈 때
- 판정이 사용자 맥락·직관과 정반대로 나왔는데 반대 근거의 구성을 안 본 상태
- 규칙 수정 뒤 이전 결과 필드를 지우려 할 때
