# 원본 이벤트 id는 사실에 부모가 둘이면 유일하지 않다

## Problem

- hots P8 `get_macro_timeline`: 웨이브·캠프·교전·오브젝트 기록을 한 시간축으로 합치며 이벤트 id = `f"{kind}:{event_ids[0]}"`.
- 합성 단위 테스트(점령 1건) 초록. "id 유일" assert도 있었다.
- 409경기 스윕: **id 중복 684건**. 원인은 원천 `camp_operations`의 규칙 — 같은 팀이 용병 생성 창(5초) 안에 두 캠프를 점령하면 두 점령 레코드에 **같은 용병 집합**을 붙이고, 그 집합의 "상대 첫 명령"(`game:57592`)도 둘 다 같다. 부모(점령)별로 펼친 하위 이벤트가 같은 원본 id를 갖게 됐다.
- 원천 계층에서는 버그가 아니었다(점령 행마다 독립 필드). **부모 단위로 펼쳐 원본 id로 다시 키잉하는 순간** 생긴 문제.

## Solution

1. 하위 사실을 부모별 이벤트로 펼칠 때 id = `kind:원본id:부모id`. 부모 없는 이벤트(1:1)는 그대로.
2. 공유를 숨기지 말고 드러낸다: 부모 이벤트에 `shares_*_with: [다른 부모 id]` — 소비자가 같은 용병을 두 번 세지 않게. 원천 규칙은 손대지 않고 문서의 한계에 적는다.
3. 회귀 테스트는 **부모 둘이 하위 사실을 공유하는 픽스처**를 일부러 만든다(deepcopy 후 두 번째 부모 추가).
4. 센서: 실데이터 전수에서 이어 붙인 페이지의 `len(ids) == len(set(ids))`. 합성 픽스처의 유일성 assert는 부모 1:1이라 뒤집힐 수 없다.

## 체크리스트

- 펼치는 하위 사실마다: "이 사실이 다른 부모에도 붙을 수 있나?"를 원천 빌더 코드(창·윈도 기반 배정)에서 확인
- 창(time window)으로 배정하는 규칙(`abs(t - parent_t) <= W`)은 부모 두 개가 W 안에 있으면 항상 공유를 만든다
