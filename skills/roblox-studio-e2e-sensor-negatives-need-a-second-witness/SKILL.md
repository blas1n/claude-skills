# Studio E2E 의 "안 됨" 신호는 두 번째 증인이 있어야 결함이다

## Problem

Roll an Anime Hero! 전수 E2E(2026-10-30)에서 센서 셋이 각각 "안 됨"을 말했고, 그중 진짜 결함은 하나였다.

| 센서가 말한 것 | 실제 | 어떻게 갈렸나 |
|---|---|---|
| `ContentProvider:PreloadAsync(ids, cb)` → 다수 `AssetFetchStatus.Failure` | **이미 화면에 그려진 그림에도 Failure** — 상태값을 믿을 수 없다 | 같은 순간 캡처에 그림이 보였다 |
| War Drummer `IsLoaded=false`, 전장에서 안 보임 | 다른 유닛 뒤에 가려졌을 뿐, 연출로 다시 띄우니 정상 | 단독으로 다시 띄워 캡처 |
| 상점 X 버튼 클릭 → `Activated` 0회, 상점 안 닫힘 | 세션 도중 **MCP 입력 도구가 클릭 전달을 멈춤**(SHOP·다른 버튼도 0회). 새 Play 세션에서 X 정상 | 대조군 버튼도 0회 → 도구 문제. 새 세션 재시도 |
| 새 유닛 첫 연출 카드 그림 빈칸 | **진짜 결함** — 미리 불러오기 없음 | 같은 카드 두 번째엔 보임 · 미리 받으니 첫 번에도 보임 |

처음엔 War Drummer 를 "로드 실패" 결함으로 보고서에 올렸다가 철회했다.

## 규칙

1. **"안 됨" 하나로 결함을 적지 않는다.** 아래 중 하나가 같은 결론을 내야 한다:
   - 그 순간의 `screen_capture` (눈으로 보이는가)
   - **새 Play 세션** 에서 재현 (업로드 직후 캐시 · 도구 상태 오염 제거)
   - 코드 경로 확인 (핸들러 연결, `GetGuiObjectsAtPosition` 으로 위를 덮는 것 없음)
2. **입력이 안 먹으면 대조군부터.** 확실히 동작하던 버튼(ROLL·SHOP)에 같은 클릭을 보내 `MouseButton1Down`/`Activated` 를 센다. 대조군도 0이면 도구 문제 — 결함 아님, "못 잼"으로 적고 새 세션에서 다시.
3. **`PreloadAsync` 콜백 상태는 판정에 쓰지 않는다.** 로드 여부는 화면(캡처)으로, "첫 표시에 보이나"는 *한 번도 안 띄운 id* 를 새 세션에서 띄워 본다.
4. **`IsLoaded` 는 발사 직후 0.3 초엔 false 일 수 있다** — 렌더 전. 캡처가 보이면 그걸 믿는다.
5. 진짜 로드 결함의 표지: **같은 것을 두 번째 띄우면 보인다.** → 고침은 접속 때 전체 목록 `PreloadAsync` (목록은 순수 함수로 빼서 "전부·중복 없음"을 유닛 테스트).

## 보고서 쓰기

- 결함 / 개선 / **못 잼(도구)** / **철회** 를 따로 칸으로 둔다. 철회한 항목도 지우지 말고 왜 틀렸는지 적는다 — 사용자가 판단 근거를 본다.

## 덤: SDXL 치비 방향

SDXL 로 뽑은 치비 캐릭터는 대부분 정면이거나 **왼쪽**을 본다. 왼쪽 진영(아군)에 쓰면 "등 돌린" 모습. 업로드 전에 얼굴·몸통·무기 방향으로 분류해 왼쪽을 보는 것만 좌우 반전하고, 목록을 스크립트에 남긴다(두 번 돌리면 원상복구되므로 1회 실행).
