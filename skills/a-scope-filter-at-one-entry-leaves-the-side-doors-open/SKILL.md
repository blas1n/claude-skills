# 진입점 한 곳의 범위 필터는 옆문을 열어 둔다

## Problem

- 상황(hots PR #50): 8개 전장의 오브젝트 사실을 `scope: "timeline"`으로 태그하고, 매크로 결정에는 넣지 않기로 했다. `cli.load_facts`에서 `decision_facts(extract(...))`로 걸렀다.
- 347경기 회귀 스윕(같은 진입점 경로로 결정 계산)은 전부 "결정 동일".
- 그런데 전체 스위트에서 `test_macro_continuation_real` 4개가 `TypeError`로 깨졌다. 테스트·연구 스크립트 40곳이 `extract()` 결과를 결정 함수에 **직접** 넘기고 있었고, 거기서는 타임라인 사실이 결정 코드에 들어가 `opening_phase()`가 None을 돌려줬다.
- 흔한 오해: "프로덕션은 CLI만 쓰니 CLI에서 거르면 충분하다." → 데이터의 생산 함수가 공개돼 있으면 소비 함수의 호출자는 진입점보다 훨씬 많다. 스윕이 진입점과 같은 경로를 쓰면 그 경로만 증명한다.

## Solution

1. **필터를 '보면 안 되는 쪽'의 입구로 옮긴다.** 소비 함수(여기선 `objective_decisions`, `camp_decisions`, `lane_decisions`, `continuation_decisions`) 첫 줄에서 `facts = decision_facts(facts)`. 진입점 필터는 남겨도 된다.
2. **필터는 멱등이고, 대상이 없으면 같은 객체를 돌려준다.** 두 번 걸러도 같고, 기존 데이터에는 비용·차이가 없다.
3. **제거한 자리에 기존 형태를 복원한다.** 새 데이터가 없던 시절 소비자가 보던 표식(여기선 `unsupported` 사실, 같은 fact_id·루프)을 넣고 원래 정렬 순서를 지킨다. 그래야 "이전과 바이트 동일"을 주장할 수 있다.
4. **원본 vs 뷰 동치 테스트**: 같은 합성 입력으로 `run(raw) == run(filtered_view)`를 단언한다. 진입점을 우회하는 호출자를 대표한다.
5. **생산 쪽 표식이 필요한지 본다.** 새 데이터가 0건인 입력(인스턴스 없는 경기)에서도 "이 범위는 제외됨"을 소비자가 알아야 하면 생산 함수가 표식을 남겨야 한다 — 필터는 없는 것을 대신 말해 줄 수 없다.

## Key Insights

- 회귀 스윕의 초록은 **스윕이 탄 경로**에 대한 증거다. 스윕이 진입점을 거치면 진입점을 우회하는 호출자는 측정되지 않는다.
- 격리 경계는 "누가 부르나"가 아니라 "누가 보면 안 되나"에 둔다.
- 실제 리플레이 테스트(`*_real`)가 먼저 깨지는 것은 신호다: 합성 테스트는 새 데이터를 만들지 않는 입력만 쓰는 경우가 많다.

## Red Flags

- "프로덕션은 X만 부르니까 X에서만 거르자"
- 생산 함수(`extract`, `build`)를 직접 import하는 테스트·스크립트가 수십 개인데 필터는 한 곳
- 격리 후 회귀 스윕은 동일한데 통합 테스트 일부만 None/KeyError로 깨짐
