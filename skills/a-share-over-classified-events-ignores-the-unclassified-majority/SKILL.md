# 분류된 것만의 비중은 분류 안 된 다수를 지운다

## Problem

리플레이 명령으로 "상황 변화 뒤에도 같은 행동을 이어 갔는가"를 판정했다(hots PR #30).
명령마다 활동 클래스(적 영웅=교전, 미니언=라인 …)를 붙이고, **분류된 명령 중** 최다 클래스의
비중 ≥ 0.6, 개수 ≥ 2 이면 "지속"으로 봤다. 일반 이동 클릭은 클래스가 없어 **조용히 제외**됐다.

dev 회귀 사례·단위 테스트는 전부 통과. 블라인드 holdout에서 두 검토자가 같은 패턴을 오탐으로 짚었다:

```
변화 후 +0.0~0.25s : 적 영웅 대상 명령 2개      → classified: hero_fight ×2 (share 1.0)
변화 후 +1.75~8s   : 동쪽으로 이동 클릭 계속   → unclassified → 판정에 없음
판정: "교전 지속"   실제: 교전 이탈
```

같은 구멍의 변형: "지점 반경 안 이동 클릭 = 오브젝트 활동"으로 이동을 **일부만** 분류하자,
지점에서 **멀어지는** 이동도 반경 안이면 활동으로 셌다(검토 후보 2/2 오탐).

## 왜 dev에서 안 보였나

- dev 사례는 "실수 후보로 검색된" 진한 순간이라 분류된 명령이 많았다(8~13개).
- 단위 테스트 픽스처도 분류되는 명령만 넣었다 — 잡음 입력을 넣을 생각을 안 했다.
- identified_at = "확인에 쓴 마지막 분류 명령"이라, 그 뒤 창 안의 행동은 **보지도 않았다**.

## Rules

1. **비중의 분모에 "분류 안 됨"을 넣거나, 따로 검사하라.** 미분류가 다수면 판정 보류 또는
   "이동/이탈"이라는 별도 클래스. "모르는 건 무시"는 "모르는 건 동의"와 같다.
2. **확인 창 전체를 봐라.** 확인 시점을 N번째 증거 직후로 자르더라도, 같은 창의 반대 증거
   (멀어지는 이동)가 없는지 검사한 뒤에 자른다.
3. **부분 분류(반경 안 이동 = 활동)는 방향을 봐라.** 거리가 줄지 않는 이동까지 활동으로 세지 마라.
4. 픽스처에 **잡음 입력**(분류 안 되는 이동 다수)을 넣은 음성 테스트를 하나 둬라.
5. holdout을 본 뒤 고치면 holdout이 dev가 된다. 발견은 다음 라운드 가설로 남기고 새 holdout으로 재라.
