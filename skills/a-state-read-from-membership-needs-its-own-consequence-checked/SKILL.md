# 멤버십으로 읽은 상태는 그 상태의 결과로 검증하라

## Problem

2026-10-30, HotS 리플레이 P2 팀 타임라인(PR #51). 킬 이후 구간의 "당시 상황"을 만들며 네 가지 상태를 단순 규칙으로 읽었고, 합성 테스트 25개가 모두 통과했다. 347경기 전수 sweep에서 넷 다 틀렸다.

| 상태 | 처음 규칙 | 실제 | 드러낸 결과 검사 |
|---|---|---|---|
| 캠프에 중립 유닛 있음 | 소유자 15, 캠프 반경 12, `Dummy` 제외 | 하나무라 장식 `LootBannerSconce`(죽지 않음), 보스 소환물 `TempleChampionTornado`, `ItemCannonball` | 점령 0.5초 뒤 잔존 유닛 = 0이어야 함 → 485건 위반(하나무라 459/459) |
| 구조물 | PR #49 공유 헬퍼 `destroyed_structures()` (`Town*` 접두어) | 요새 잔해 `TownHallDestroyed`, 캠프 표식 `TownMercCampCaptureBeacon`도 포함. 기존 사실 계층은 레지스트리 접두어로 거르고 있었음 | 종류별 잔존 수에 `other` 6개가 팀 미상으로 뜸 |
| 오브젝트 인스턴스 열림 | 마지막 단계 ≠ ended | 저주받은 골짜기·광산은 **ended 뒤에 reward**가 옴 → 끝난 인스턴스가 다시 열림 | 문맥 상태 분포에 `reward_observed` 3,029건(수정 후 1,075) |
| 경기 진행 중 | 헤더 `m_elapsedGameLoops` | 핵 파괴 뒤 종료 연출을 16.6~71.9초(p50 19초) 더 녹화 | 핵 파괴 시각 − 리플레이 끝 분포 |

## 원칙

1. **상태마다 "참이면 반드시 따르는 결과"를 하나 적고 전수로 잰다.** 점령 직후 캠프 유닛 0, 닫힌 인스턴스 뒤 열린 단계 0, 경기 종료 뒤 기준점 0, 구조물 종류 `other` 0. 100%가 아니면 위반 사례의 유형을 세라 — 위반은 한두 전장/유형에 몰려 있고, 그 이름이 원인을 말해준다.
2. **공유 헬퍼를 다른 계층에서 꺼내 쓸 때, 원래 호출자가 뒤에서 하던 필터를 확인하라.** 헬퍼의 테스트는 원래 호출자 경로만 지킨다.
3. **"마지막 이벤트 = 현재 상태"는 단계 순서가 선형이라는 가정이다.** 종단 단계(ended)가 있으면 그것을 우선하고, 그 뒤 단계는 부속 정보로 둔다.
4. **녹화 길이는 관찰 상한이지 사건 종료가 아니다.** 도메인의 종료 사건(핵 파괴)이 있으면 그것으로 검열하고 basis를 기록한다.
5. 제외 목록을 만들었으면 같은 결과 검사로 **0이 되는 것을 확인**하고(485 → 0), 그 목록을 테스트 파라미터로 고정한다.

## 하지 말 것

- 합성 픽스처 통과를 상태 규칙 검증으로 여기기 — 픽스처에는 내가 상상한 멤버만 있다.
- 위반을 "노이즈"로 보고 비율만 보고하기 — 하나무라처럼 한 전장 100% 위반은 규칙 결함이다.

## 사례 추가: "종료 이벤트 없음"은 먼저 층별로 나눠라 (2026-10-30, PR #51 후속)

첫 보고에서 347경기 중 30경기가 `KingsCore` 파괴가 없어 "원인 미확인(조기 이탈·절단 추정 불가)"으로 리플레이 끝을 썼다. 후속 조사에서 30경기를 **전장으로 나누자 전부 알터랙 고개(그 전장 전부)**였고, 그 전장의 핵은 다른 유닛(`VanndarStormpike`·`DrekThar`)이었다.

- 결정적 근거는 독립된 결과 두 개였다: 핵(보스) 사망 → `SScoreResultEvent`가 347경기 모두 정확히 7.0625초, 핵을 잃은 팀 = 패배 팀 347/347.
- 교훈: 빠진 이벤트를 "원인 미확인"으로 보고하기 전에 맵·빌드·모드로 층화하라. 한 층에 100% 몰려 있으면 결측이 아니라 **그 층에서 이름이 다른 같은 사건**이다.
- 같은 후속에서 크레딧 없는 상대 사망(41건)도 원본 값(0·AI 11/12·중립 15)을 세어 "판단 불가"와 "크레딧 없음"을 나눴다. 값 분포를 먼저 보면 `unknown`을 정의할 근거가 생긴다.
