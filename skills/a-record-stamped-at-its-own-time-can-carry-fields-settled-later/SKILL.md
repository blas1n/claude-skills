# 자기 시각에 찍힌 레코드도 나중에 정해진 필드를 담을 수 있다

## Problem (hots P8 `get_macro_timeline`, PR #66 보완)

`as_of` 필터는 `known_at > as_of` 이벤트를 빼고 시간 필드를 검사했다. 시간 필드 누출 0건, 409경기 스윕 통과. 리뷰 지적 후 다시 보니:

| 모양 | 사례 | 크기 |
|---|---|---|
| 대칭 창 배정 | 점령 레코드의 `merc_event_ids` = 점령 ±5초 안에 태어난 용병; `shares_mercs_with` = 다른 점령 | 수정 전 코드 60경기 스윕에서 id 누출 6건 |
| 나중 이벤트로 정한 결과 | 알터랙 `ended`(마지막 포로 사망 시각)의 `winner_team` = 30초 안 보상 기병 소유 팀. 원천 모듈 문서는 "winner is never visible earlier" | 120/120건, 최대 11.56초 앞서 |
| 소급 삽입 | 하늘 사원 preview: 활성화 이벤트 때 최대 35초 전 수호자 생성을 preview로 끼움 | preview가 활성화 예고가 됨 |
| 부재로 정한 값 | 종료 이벤트가 끝까지 없는 구슬 `unresolved`, 경기 전체 `lane_basis`, `game_end_seconds` | 1,739 / 316,850 구슬 |

이 값들은 시각 필드가 아니라 **값·id·레코드 존재** 자체라 시간 필드 검사로는 안 보인다.

## Solution

1. 필드별 표: "이 값은 언제 알 수 있나 + 근거 코드 줄". 창 배정은 창 끝(부모 시각 + W), 쌍 관계는 둘 중 늦은 쪽 + W, 결과는 결정 이벤트 시각(`*_known_at`), 소급 레코드는 그것을 만든 이벤트 시각, 부재 값은 as_of에서 `pending`/`null`.
2. 원천 빌더에 evidence id가 있으면 **전수로 지연을 잰다**: `max(evidence 시각) − fact 시각 > 0`인 (규칙, 단계, grade) 조합 목록. 소급 삽입은 지연에 안 잡히니(근거는 과거) 빌더 코드에서 "나중 이벤트 처리 중 과거 레코드를 insert"하는 곳을 찾는다.
3. 검사기: 응답을 문자열화해 `tracker|game|message:N` 전부를 원본 시각과 대조. 
   - 같은 id를 나중 시각의 파생 레코드가 재사용할 수 있다(사망 id를 쓰는 `hero_alive_confirmed`) → id 시각은 **최솟값**. 안 그러면 가짜 누출.
   - 산출물에 시각이 없는 id(용병 생성)는 같은 스트림에서 그 이하 인덱스의 최대 시각을 하한으로(이벤트가 루프 순서로 저장될 때).
   - 합성 픽스처는 모든 id에 시각을 주고 "미등록 id 0"을 함께 단언 — 모르는 id로 통과하지 못하게.
4. 뒤집힘 확인: 수정 전 커밋을 `git archive`로 풀어 같은 스윕을 돌려 누출이 나오는지 본다(`src`는 옛것, `tests`는 새것: cwd=옛 트리, PYTHONPATH=새 트리, 버전 해시용 config/uv.lock도 함께 풀기).
5. 원천 계층의 같은 결함은 호환성 때문에 고치지 않더라도 문서 한계에 **구체적으로** 남긴다.
