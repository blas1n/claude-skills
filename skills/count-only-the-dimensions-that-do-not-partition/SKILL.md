# 분할 차원은 합산하고, 겹치는 차원만 따로 받아라

## Problem
hpgg: 티어표·영웅 상세를 "지역 × 구간" 동시 필터로 만들려고 칸을 셈. QM 4(전체+KR/NA/EU) + SL 4×3(전체/브실골플/다마그) = 16칸, 칸마다 통계 + 파티 보정용 솔로 호출 → **하루 32회** > Intermediate 한도 30회. 갱신 주기 타협(격일 등) 선택지를 내밀었다.
- 사용자: "왜 32회야? 전체를 가져온 다음 지역 분리가 안 되면, 지역별만 가져와서 전체에 합산하면 안 돼?"
- 이미 가진 이전 패치 데이터(전체 + KR/NA/EU 모두 있음)로 대조: KR+NA+EU 의 승/패가 전체 파일과 **QM 1,440행·SL 1,170행 전부 정확히 일치**(한 경기는 한 서버에서만, CN 은 2023 종료). 밴은 비율에서 역산이라 반올림 오차만.
- 반면 구간은 한 경기가 참가자 각자의 구간에 중복 집계 → 구간 합 24,243 > SL 전체 16,980. 분할 아님.
- 결과: 지역 12칸만 받고 전체 4칸은 합산 → **하루 24회**, 16칸 전부 매일. 타협 불필요.

## Solution
1. 차원마다 판정: 한 사건(경기·주문·세션)이 그 차원의 값 **하나에만** 속하나? (서버·지역·플랫폼은 대개 예, 플레이어 등급·태그·카테고리 다중 소속은 대개 아니오)
2. 이미 가진 데이터로 증명: 부분 파일들의 카운트 합 == 전체 파일, **행 단위**(키별)로. 비율 필드는 합하지 말고 카운트에서 재계산. 역산된 카운트는 반올림 허용치를 기록.
3. 분할 차원: 하위 칸만 수집하고 전체는 합산(코드 한 곳, 테스트로 "전체 = Σ 부분" 고정). 부분 하나라도 실패하면 전체를 갱신하지 마라 — 같은 이름의 다른 숫자가 된다.
4. 겹치는 차원: 칸마다 받는다. 예산은 이것만으로 계산.
5. 보정 계수 같은 파생값도 같은 원리: 보정 입력(여기선 솔로 표본)도 분할 차원에서 합산해 전체 보정에 쓴다.

## Key Insights
- "칸 수 × 호출"은 상한이지 필요량이 아니다. 분할 차원의 "전체" 칸은 공짜다.
- 증명 비용은 0: 같은 시점의 전체와 부분을 이미 갖고 있으면 행 단위 대조로 끝난다.
- 예산이 안 맞을 때 갱신 주기·범위 타협 메뉴를 내기 전에, 이 질문부터: "이 칸은 다른 칸들의 합인가?"

## Red Flags
- 전체 값과 지역별 값을 둘 다 API 로 받고 있음
- 예산 초과 → 첫 대응이 "격일/순환 수집"
- 비율(%) 필드를 그대로 합산하려 함
